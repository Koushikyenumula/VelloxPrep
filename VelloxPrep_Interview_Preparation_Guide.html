Project Story

Confidently explain the project to any interviewer without going deep into implementation.

1.1 What is VelloxPrep?

VelloxPrep is a full-stack, AI-powered interview preparation platform built with Java 21, Spring Boot 3.4, PostgreSQL, and Google Gemini AI. It transforms passive interview studying into an active, intelligent simulation experience.

The problem it solves: Traditional interview preparation involves reading generic question-answer lists. There's no personalization, no feedback, and no way to gauge actual readiness. Candidates don't know what they're weak at until they fail a real interview.

Target users: Software engineering candidates preparing for technical interviews — backend, frontend, data science, DevOps, and related roles.

Why AI is useful: AI enables three things that static resources can't: (1) generating tailored questions based on the candidate's resume and target role, (2) evaluating free-form answers with detailed feedback and scoring, and (3) adapting difficulty based on the candidate's level.

Overall purpose: Give candidates a private, AI-powered mock interviewer they can practice with any time — covering standard interviews, resume-based interviews, MCQ quizzes, and coding challenges — while tracking progress over time.

1.3 Major Features

User Authentication (JWT + OAuth)

What it does: Users register with email/password or sign in via Google/GitHub OAuth. Each session is authenticated with a JWT token.

Why it exists: Every user needs a private account to store their resumes, sessions, and progress securely.

How it works: On login, Spring Security validates credentials against BCrypt-hashed passwords in PostgreSQL. JwtService generates a signed JWT with the user's email and role. The frontend stores this token in localStorage and sends it as Authorization: Bearer <token> with every API request. The JwtAuthenticationFilter intercepts requests, validates the token, and populates the SecurityContext.

Resume Upload & Management

What it does: Upload PDF resumes, view upload history, delete old resumes.

Why it exists: Resumes are the source data for personalized interview generation and ATS scoring.

How it works: Multipart file upload → validation (PDF only, ≤10MB) → saved to uploads/ directory with UUID-prefixed filename → metadata stored in PostgreSQL → Apache PDFBox extracts text → AtsScoreService generates ATS score via Gemini → SkillExtractionService extracts skills via Gemini.

AI Interview Generation (Standard & Resume-Based)

What it does: Generates 10 technical interview questions based on a chosen skill/difficulty, or based on the candidate's uploaded resume.

Why it exists: Unique, targeted questions that match the candidate's actual experience and desired difficulty level.

How it works: The backend constructs a structured prompt with a system instruction telling Gemini to respond in JSON format. For resume-based interviews, extracted skills from the resume are injected into the prompt. Gemini returns a JSON array of {question, expectedAnswer} objects. These are parsed with Jackson's ObjectMapper, stored as InterviewQuestion entities linked to an InterviewSession.

AI Answer Evaluation

What it does: After submitting a free-text answer, Gemini evaluates it against the expected answer and returns a score (0–100) plus detailed feedback.

Why it exists: Transforms passive Q&A reading into an active feedback loop — the candidate knows exactly what was good, what was missing, and how to improve.

How it works: The prompt includes the question, expected answer, and user's answer. Gemini returns {score, aiFeedback}. The response is parsed, stored as an AnswerEvaluation entity, and the session's overall score is recalculated as the average of all evaluations. When all questions are answered, the session status changes to COMPLETED and a Progress record is created.

MCQ Assessment Engine

What it does: Generates multiple-choice quizzes with instant grading.

Why it exists: MCQs test breadth of knowledge quickly — useful for screening-style preparation.

How it works: Similar to interview generation — Gemini generates MCQ objects with options and correct answers. Answers are validated server-side and scored instantly.

Mock Coding Tests

What it does: Timed coding challenges where users write code, run against test cases, and submit for evaluation.

Why it exists: Simulates real coding interview environments like HackerRank/LeetCode.

How it works: Gemini generates coding problems. Users write solutions in a browser-based editor. Code is submitted, evaluated by Gemini, and results are stored in CodingSubmission entities.

Performance Dashboard & Progress Tracking

What it does: Displays total sessions, average scores, score trends over time, recent activity, and strongest/weakest areas.

Why it exists: Candidates need to see their improvement trajectory and focus areas.

How it works: DashboardService aggregates data from InterviewSession, McqSession, CodingSession, and Progress repositories. The frontend renders the data with numeric counters, charts, and session cards.

Admin Console

What it does: Platform administrators can view all users, platform statistics, promote/demote user roles, and delete users.

Why it exists: Every production platform needs administrative oversight and user management.

How it works: Endpoints under /admin/** are restricted to ROLE_ADMIN via Spring Security's .hasRole("ADMIN"). AdminService provides user listing, statistics aggregation, and role modification.

Theme System & Mobile Performance

What it does: Dark/light theme toggle with persisted preference. On mobile, the neural canvas particle engine automatically reduces from 80+ nodes to 14, caps DPR at 1, disables mouse-follower effects, and pauses rendering during scrolling.

Why it exists: Premium visual experience on desktop without sacrificing mobile performance.

2.3 Backend Architecture

Controller Layer

Controllers are thin entry points — they handle HTTP mapping, extract parameters, and delegate to services. They should never contain business logic.

Why separate from services? (1) Single Responsibility — controllers handle HTTP, services handle logic. (2) Testability — services can be unit-tested without HTTP concerns. (3) Reusability — the same service can be called from different controllers, scheduled tasks, or message listeners.

VelloxPrep has 13 controllers, each annotated with @RestController and @RequestMapping.

Service Layer

Each service has an interface (e.g., AuthService) and an implementation (e.g., AuthServiceImpl). This follows the Dependency Inversion Principle — controllers depend on abstractions, not concrete classes.

Key services and their responsibilities:

  • AuthServiceImpl — Registration (BCrypt hashing) and login (password verification + JWT generation)
  • GeminiServiceImpl — Builds HTTP requests to Gemini API, parses responses, handles errors
  • InterviewQuestionServiceImpl — Prompt construction, AI question generation, JSON parsing, session creation
  • AnswerEvaluationServiceImpl — Sends user answers to Gemini for scoring, updates session scores
  • ResumeServiceImpl — PDF validation, file storage, metadata persistence, triggers ATS analysis

Repository Layer

Repositories extend JpaRepository<Entity, Long>. Spring Data JPA auto-generates SQL from method names like findByEmail(String email) or findByUserEmail(String email). No SQL is written manually.

Entity Layer

JPA entities are Java classes annotated with @Entity and @Table. Each entity maps to a PostgreSQL table. Relationships are defined with @OneToMany, @ManyToOne, and @JoinColumn. Hibernate's ddl-auto: update auto-creates/modifies tables from entity definitions.

DTO Layer

DTOs (Data Transfer Objects) separate the API contract from the database model. Benefits: (1) Don't expose internal fields (password, audit columns). (2) API can evolve independently of the database. (3) Input DTOs carry validation annotations (@NotBlank, @Email).

Exception Layer

GlobalExceptionHandler is annotated with @RestControllerAdvice. It catches specific exceptions and returns consistent ApiResponse JSON. For example, InvalidCredentialsException → 401, ResourceNotFoundException → 404, GeminiApiException → 503, AccessDeniedException → 403.

config/SecurityConfig.java

Defines the SecurityFilterChain bean: CORS configuration, CSRF disabled, stateless sessions, public vs authenticated endpoints, admin role restriction, and JWT filter injection before UsernamePasswordAuthenticationFilter.

Three core methods: generateToken(email, role), extractEmail(token), isTokenValid(token). Uses HMAC-SHA signing with a Base64-decoded secret key.

security/JwtAuthenticationFilter.java

Extends OncePerRequestFilter. The 7-step process: extract token → validate → extract email → check SecurityContext is empty → load UserDetails → create auth token → set SecurityContext.

Builds JSON request bodies with Jackson's ObjectMapper. Calls /v1beta/models/{model}:generateContent?key={apiKey}. Parses candidates[0].content.parts[0].text from the response. Sets responseMimeType: "application/json" in generation config to get structured JSON back.

2.6 Authentication Architecture (Step-by-Step)

  1. Registration: POST /auth/register → AuthServiceImpl checks if email exists → hashes password with passwordEncoder.encode() (BCrypt) → saves User entity with Role.USER
  2. Login: POST /auth/login → finds user by email → passwordEncoder.matches(rawPassword, hashedPassword) → if valid, jwtService.generateToken(email, role)
  3. JWT Generation: Jwts.builder().subject(email).issuer("ai-interview-platform").expiration(now + 86400000ms).claims(Map.of("role", role)).signWith(hmacKey).compact()
  4. Client Storage: Frontend stores token in localStorage.setItem('token', data.token)
  5. Authenticated Request: auth.js injects Authorization: Bearer {token} header on every fetch() call
  6. Server Validation: JwtAuthenticationFilter extracts token → jwtService.isTokenValid() parses and checks expiry → extracts email → loads UserDetails from DB → creates UsernamePasswordAuthenticationToken → sets SecurityContextHolder
  7. Authorization: SecurityConfig checks: /admin/** → hasRole("ADMIN"), all other authenticated endpoints → user must have valid JWT
Key Concepts to Know BCrypt: Adaptive hash function with salt — same password produces different hashes each time.
JWT Structure: Header (alg) . Payload (sub, role, exp, iss) . Signature (HMAC-SHA).
Stateless Auth: Server stores NO session. Every request carries full authentication proof in the JWT.
OncePerRequestFilter: Guarantees the filter runs exactly once per HTTP request, even with forwards/includes.

2.9 Interview Session Lifecycle

  1. Create Session: User configures skill + difficulty → POST /interviews/generate
  2. Generate Questions: Service constructs prompt → Gemini returns 10 Q&A pairs → parsed and stored as InterviewQuestion entities → Session status: IN_PROGRESS
  3. Display Questions: Frontend fetches session via GET /interview-sessions/{id} → renders Q&A interface
  4. Submit Answer: User types answer → POST /interview/answer with {questionId, answer}
  5. AI Evaluation: Service builds evaluation prompt (question + expected + user answer) → Gemini returns {score, aiFeedback} → stored as AnswerEvaluation
  6. Calculate Results: After all questions answered → average all scores → update session score → set status to COMPLETED
  7. Update Progress: Progress record created linking user, skill, score, and timestamp
  8. Dashboard Update: Next dashboard load aggregates latest session data

3.1 Java Questions

Why did you use interfaces for your service layer?
Testing: OOP principles, Dependency Inversion, Spring DI
Following the Dependency Inversion Principle — controllers depend on the AuthService interface, not AuthServiceImpl. This means I can swap implementations without touching controllers, and I can mock services in unit tests. Spring's IoC container injects the concrete implementation at runtime via @RequiredArgsConstructor.
What if you had multiple implementations of the same interface?
Where do you use the Builder pattern in VelloxPrep?
Design patterns, practical usage
Everywhere. Lombok's @Builder is on every entity (User.builder().name("...").email("...").build()), every DTO response (ApiResponse.builder().status(200).message("...").data(...).build()), and the JWT builder (Jwts.builder().subject(email).signWith(key).compact()). The Builder pattern is ideal when constructing objects with many optional fields — it's more readable than telescoping constructors.
How does Lombok's @Builder work under the hood?
Do you use Java Streams in your project?
Functional programming, practical Stream usage
Yes. For example in ResumeServiceImpl.getUserResumes(), I use resumes.stream().map(resume -> ResumeHistoryResponse.builder()...build()).toList() to transform entity lists into DTO lists. Also in InterviewQuestionServiceImpl to map questions to response DTOs, and in GlobalExceptionHandler to collect field validation errors.
How does dependency injection work in your project?
Spring IoC, constructor injection
I use constructor injection via Lombok's @RequiredArgsConstructor. All dependencies are declared as final fields, and Lombok generates a constructor that Spring uses to inject the beans. For example, AuthServiceImpl has final UserRepository userRepository, final PasswordEncoder passwordEncoder, final JwtService jwtService — all injected automatically.
Why constructor injection over field injection (@Autowired)?

3.2 Spring Boot Questions

What Spring Boot starters does your project use?
Understanding of starter dependencies
spring-boot-starter-web (REST API, embedded Tomcat), spring-boot-starter-data-jpa (Hibernate + JPA), spring-boot-starter-security (Spring Security), spring-boot-starter-validation (Jakarta Bean Validation), spring-boot-starter-actuator (health/metrics), spring-boot-starter-mail (SMTP). Each starter brings a curated set of dependencies and auto-configuration.
How does @RestControllerAdvice work in your GlobalExceptionHandler?
Exception handling, AOP concepts
@RestControllerAdvice combines @ControllerAdvice and @ResponseBody. It acts as a global catch block for all controllers. When an exception is thrown from any controller, Spring checks the handler for a matching @ExceptionHandler method. My handler maps InvalidCredentialsException → 401, ResourceNotFoundException → 404, GeminiApiException → 503, AccessDeniedException → 403, MethodArgumentNotValidException → 400 with field-level error details. The catch-all Exception.class handler returns 500 and logs the full stack trace.
How is your application.yml structured?
Configuration management, externalization
It's organized by concern: spring.datasource (PostgreSQL URL, credentials from env vars), spring.jpa (Hibernate dialect, ddl-auto: update), server (port 8080, context-path /api), app.jwt (secret, expiration-ms: 86400000 = 24h), app.gemini (api-key, model, temperature: 0.7, max-output-tokens: 2048), springdoc (Swagger UI path). Sensitive values use ${ENV_VAR:default} syntax for externalization.

3.3 Spring Security Questions

Walk me through your SecurityFilterChain configuration.
Deep security understanding
In SecurityConfig.securityFilterChain(): First, I enable CORS with a custom CorsConfigurationSource that allows specific origins. Then CSRF is disabled because it's a stateless REST API — no cookies or sessions to protect. Session management is set to STATELESS. A custom JwtAuthenticationEntryPoint handles 401 errors with JSON responses. Authorization rules: /auth/**, /health/**, /swagger-ui/**, and /actuator/** are permitAll(). /admin/** requires hasRole("ADMIN"). Everything else requires authentication. Finally, I add JwtAuthenticationFilter before UsernamePasswordAuthenticationFilter.
Why do you add JWT filter BEFORE UsernamePasswordAuthenticationFilter?
What's the difference between authentication and authorization?
Fundamental security concepts
Authentication = "Who are you?" — verifying identity (JWT token validation, password check). Authorization = "What can you do?" — checking permissions (ROLE_USER can access /interviews, only ROLE_ADMIN can access /admin). In VelloxPrep, authentication happens in JwtAuthenticationFilter; authorization happens in SecurityFilterChain's .authorizeHttpRequests() rules.
Why is CSRF disabled? Isn't that insecure?
Understanding of CSRF attack vectors
CSRF (Cross-Site Request Forgery) exploits the browser's automatic cookie attachment. Since VelloxPrep uses JWT tokens in the Authorization header (not cookies), the browser doesn't automatically attach credentials to cross-site requests. Therefore CSRF protection is unnecessary and actually counterproductive for stateless REST APIs.
What happens when a user sends an expired JWT?
Error handling, security edge cases
In JwtAuthenticationFilter, jwtService.isTokenValid(token) calls Jwts.parser().parseSignedClaims(token), which throws an ExpiredJwtException. This is caught by the generic catch (Exception ex) block, which logs a warning and lets the filter chain continue without setting authentication. Since no SecurityContext is populated, SecurityFilterChain rejects the request, and JwtAuthenticationEntryPoint returns a 401 JSON response.

3.4 JPA / Hibernate Questions

Explain the User-InterviewSession relationship.
JPA relationships, cascade, fetch types
It's a @OneToMany from User to InterviewSession — one user has many sessions. In User.java: @OneToMany(mappedBy = "user", cascade = CascadeType.ALL, orphanRemoval = true). The mappedBy says the InterviewSession entity owns the foreign key. CascadeType.ALL means save/delete operations propagate from User to their sessions. orphanRemoval = true means if a session is removed from the user's list, it gets deleted from the database. On the InterviewSession side: @ManyToOne(fetch = FetchType.LAZY) @JoinColumn(name = "user_id").
What is the N+1 problem and how does your project handle it?
What is @BatchSize and why do you use it?
Performance optimization, N+1 awareness
@BatchSize(size = 20) on InterviewSession.interviewQuestions tells Hibernate: when lazily loading questions for multiple sessions, fetch them in batches of 20 using WHERE session_id IN (?, ?, ...) instead of one query per session. This mitigates the N+1 problem — instead of 100 queries for 100 sessions, it takes ~5 queries.

3.5 PostgreSQL Questions

Why PostgreSQL instead of MySQL or MongoDB?
Database selection reasoning
The data model is inherently relational — users own sessions, sessions contain questions, questions have evaluations. These are well-defined relationships with referential integrity requirements. PostgreSQL was chosen over MySQL for its superior JSON support (useful if AI responses need flexible storage), better standards compliance, and strong community. MongoDB was not appropriate because the data is structured with clear relationships — a document database would require embedding or manual joins.

3.6 REST API Questions

Explain your API response envelope.
API design consistency
Every endpoint returns ApiResponse<T> — a generic wrapper with status (HTTP code), message (human-readable), data (payload, generic type T), and timestamp. Factory methods: ApiResponse.success("msg", data), ApiResponse.created("msg"), ApiResponse.error(status, "msg"). The @JsonInclude(NON_NULL) annotation ensures null fields are omitted from the JSON output. This gives clients a predictable structure for all responses — success and error.
Give me an example of POST vs PUT usage in your project.
HTTP semantics
POST /auth/register — creates a new resource (user). POST /interviews/generate — creates a new interview session. PUT /users/password — updates an existing resource (password change). PUT /admin/users/{id}/role?role=ADMIN — updates user's role. POST creates, PUT updates. DELETE removes (DELETE /resumes/{id}).

3.7 Gemini / AI Questions

Why Gemini instead of OpenAI/GPT?
Technology selection reasoning
Gemini was chosen for: (1) generous free tier for development and small-scale deployment, (2) native JSON-mode support (responseMimeType: "application/json") which produces cleaner structured output, (3) Google's ecosystem integration, and (4) competitive quality for structured generation tasks like question creation.
What happens if Gemini returns invalid JSON?
Error handling, resilience
In AnswerEvaluationServiceImpl, the code first tries to locate JSON boundaries using indexOf('{') / lastIndexOf('}') to extract the JSON object even if surrounded by extra text. If no valid JSON object is found, it throws GeminiApiException. The ObjectMapper.readTree() call is wrapped in a try-catch — any parse failure throws GeminiApiException("Failed to parse AI evaluation response"). The GlobalExceptionHandler catches this and returns HTTP 503 to the client.
How would you improve this to be more resilient? (Retry logic, fallback responses, caching)
Why shouldn't the frontend call Gemini directly?
Security architecture
Three reasons: (1) API key exposure — the key would be visible in browser DevTools/network tab. (2) No server-side validation — can't verify the user owns the session or has permission. (3) No persistence — generated questions need to be stored in the database, which requires server-side processing.

3.8 Resume / ATS Questions

How does PDFBox work in your project?
Third-party library integration
Apache PDFBox is a Java library for working with PDF documents. In VelloxPrep, after a resume PDF is saved to disk, the SkillExtractionService and AtsScoreService use PDFBox to load the PDF and extract its text content. This extracted text is then sent to Gemini for AI analysis — skill extraction and ATS scoring. PDFBox handles the binary PDF format parsing, stripping formatting, and returning plain text.

3.9 Frontend Questions

How does your frontend handle JWT authentication?
Client-side auth implementation
auth.js stores the JWT in localStorage after login. It wraps the global fetch function to automatically inject Authorization: Bearer {token} on every request. On page load, each page checks if a token exists — if not, it redirects to login.html. The auth interceptor watches for 401 responses; if it receives one (excluding password-change and auth endpoints), it clears the token and redirects to login.
What is the VisualEngine and why did you create it?
Performance optimization, architecture decisions
VisualEngine is a centralized visual effects module in components.js that manages theme switching, particle canvas rendering, cursor glow, card spotlights, and scroll reveals. I centralized it because every page was duplicating the same canvas/cursor/theme code. The engine automatically detects touch devices ('ontouchstart' in window || navigator.maxTouchPoints > 0) and applies mobile optimizations — 14 particles instead of 80+, DPR capped at 1, disabled mouse tracking, and paused rendering during scrolling — to maintain 60fps on phones.

3.10 Docker / Deployment Questions

Explain your Dockerfile.
Containerization knowledge
It's a multi-stage build. Stage 1 (build): Uses maven:3.9-eclipse-temurin-21-jammy image, copies pom.xml and src/, runs mvn clean package -DskipTests to produce the JAR. Stage 2 (runtime): Uses the lighter eclipse-temurin:21-jre-jammy image (no JDK, no Maven), copies only the built JAR, exposes port 8080, runs java -jar app.jar. The multi-stage approach reduces the final image size dramatically — the build tools stay in stage 1 and are discarded.

3.11 Project-Specific "Trap Questions" (30+)

1. Why JWT instead of sessions?
VelloxPrep is a REST API consumed by a static frontend — there's no server-side session store. JWTs make the API stateless: every request carries its own authentication proof. This simplifies horizontal scaling (no shared session store needed) and makes the API consumable by any client (web, mobile, CLI).
2. Where exactly is JWT validated in your code?
JwtAuthenticationFilter.doFilterInternal() → calls jwtService.isTokenValid(token) → which calls Jwts.parser().verifyWith(signingKey).build().parseSignedClaims(token). This validates the signature (HMAC-SHA) and checks expiry.
3. What happens if the JWT secret is compromised?
An attacker could forge valid JWTs for any user/role. Mitigation: rotate the secret immediately (all existing tokens become invalid, forcing re-login). The secret is stored as an environment variable, never in source code.
4. Why BCrypt instead of SHA-256 for passwords?
SHA-256 is fast — that's bad for password hashing because GPUs can brute-force billions of SHA-256 hashes/second. BCrypt is intentionally slow (configurable rounds) and includes a random salt per hash, making rainbow table attacks impossible and brute-force impractical.
5. What happens when a non-admin user accesses /admin/users?
SecurityFilterChain checks .hasRole("ADMIN") → the user's authority is ROLE_USER → access denied → AccessDeniedException → GlobalExceptionHandler returns 403 Forbidden.
6. What is the relationship between User and InterviewSession in the database?
One-to-Many: users.id ← interview_sessions.user_id (foreign key). In JPA: @ManyToOne(fetch = FetchType.LAZY) on InterviewSession, @OneToMany(mappedBy = "user") on User. Cascade ALL with orphan removal — deleting a user deletes their sessions.
7. How are AI-generated questions stored?
Gemini returns a JSON array of {question, expectedAnswer}. InterviewQuestionServiceImpl parses this with Jackson's ObjectMapper.readTree(), iterates the JSON array, creates InterviewQuestion entities, links them to the InterviewSession via session.addQuestion(), and saves everything with sessionRepository.save(session) — JPA cascades the save to all child questions.
8. What happens if Gemini is down?
RestClientException is thrown by Spring's RestClient. GeminiServiceImpl catches it and wraps it in GeminiApiException. GlobalExceptionHandler catches GeminiApiException and returns HTTP 503 (Service Unavailable) with an error message. The frontend shows the error to the user. Future improvement: retry with exponential backoff, circuit breaker pattern.
9. Why do you use a service-interface pattern instead of concrete classes?
Dependency Inversion Principle. Controllers depend on abstractions (interfaces), not implementations. Benefits: mockability in tests, swappable implementations (e.g., swap GeminiService for an OpenAI implementation without changing any controller), clean separation of contract vs implementation.
10. Why is your API base path /api?
Set via server.servlet.context-path: /api in application.yml. This provides a clean namespace separation — all backend endpoints live under /api/*, making it easy to route at the reverse proxy level (e.g., /api → backend, everything else → frontend static files).
11. How would you scale this to 100,000 users?
Current bottleneck: Gemini API rate limits and single-server architecture. Solutions: (1) Horizontal scaling — since auth is stateless (JWT), add more Spring Boot instances behind a load balancer. (2) Database connection pooling (HikariCP is already included). (3) Redis cache for dashboard aggregations. (4) Queue AI requests through a message broker (RabbitMQ/Kafka) to handle rate limits. (5) CDN for frontend static assets.
12. What's your biggest bottleneck?
The Gemini API call. Question generation takes 2-5 seconds depending on load. Each answer evaluation is another API call. For a 10-question interview, that's 11 sequential API calls. Improvements: batch evaluation requests, cache similar questions, pre-generate question pools.
13. How do you prevent malicious file uploads?
ResumeServiceImpl.validateFile() checks: (1) file is not null/empty, (2) content type is exactly application/pdf, (3) file size ≤ 10MB. Files are saved with UUID-prefixed names to prevent path traversal. Could improve: magic byte validation (check PDF header bytes), virus scanning, sandboxed parsing.
14. Why store files on disk instead of a database or cloud storage?
Simplicity for the current scale. The uploads/ directory is a direct file system path. Limitation: doesn't survive container restarts on Render's free tier. Production improvement: migrate to AWS S3 or Google Cloud Storage for persistent, scalable blob storage.
15. What happens if two requests update the same session score simultaneously?
Potential race condition. Both transactions read the current score, calculate a new average, and write — the second write could overwrite the first. Current mitigation: @Transactional provides database-level isolation. Improvement: optimistic locking with @Version on the session entity, which throws OptimisticLockingFailureException on conflict.
16. Why didn't you use React or Angular for the frontend?
VelloxPrep's frontend is page-based, not a single-page app. Each page has a specific purpose with relatively simple state. Vanilla JS gives full control over DOM, Canvas API, and performance without framework overhead (virtual DOM diffing, bundling complexity). For a larger team or more complex client-side routing, React would be justified.
17. How does your CORS configuration work?
SecurityConfig.corsConfigurationSource() allows specific origins (localhost:5500, render.com, vercel.app), specific methods (GET, POST, PUT, DELETE, etc.), specific headers (Authorization, Content-Type), and exposes the Authorization header. allowCredentials(true) allows cookies/auth headers in cross-origin requests.
18. Why does CustomUserDetailsService use email as the username?
The loadUserByUsername(String email) method queries UserRepository.findByEmail(). In VelloxPrep, email is the unique identifier for authentication — it's the JWT subject and the login credential. Spring Security's UserDetails interface requires a "username" concept; we map email to that role.
19. What would you change if you rebuilt this project?
(1) Use Spring WebFlux for non-blocking Gemini API calls. (2) Add Redis caching for dashboard data. (3) Implement refresh token rotation. (4) Use AWS S3 for resume storage. (5) Add WebSocket for real-time evaluation feedback. (6) Implement a question cache to reduce Gemini API usage. (7) Add rate limiting to prevent API abuse.
20. How would you implement refresh token rotation?
Store refresh tokens in the database with a revoked flag. On token refresh: validate the refresh token, generate a new access + refresh token pair, revoke the old refresh token. If a revoked refresh token is used (indicating theft), revoke all tokens for that user.
21. Why is ddl-auto set to 'update' and not 'validate' in production?
Strictly speaking, update is convenient for development — Hibernate auto-creates/modifies tables. In production, validate or none is safer to prevent accidental schema changes. Database migrations should be handled by tools like Flyway or Liquibase. This is an area for improvement in VelloxPrep.
22. How do you handle the Gemini API key in different environments?
The key is injected via the GEMINI_API_KEY environment variable, referenced in application.yml as ${GEMINI_API_KEY:your_api_key_here}. It's never committed to Git (listed in .gitignore via .env). On Render, it's set in the environment variables dashboard.
23. What is @Transactional and where do you use it?
@Transactional wraps a method in a database transaction — if any exception occurs, all changes are rolled back. I use it on service methods like register(), uploadResume(), submitAnswer(). For read-only operations like getUserResumes(), I use @Transactional(readOnly = true) which hints Hibernate to optimize (skip dirty checking).
24. How does your ApiResponse generic wrapper work?
ApiResponse<T> uses Java generics — the T can be LoginResponse, List<ResumeHistoryResponse>, Void, or Map<String, String> (validation errors). Factory methods like ApiResponse.success("msg", data) use <T> type inference. @JsonInclude(NON_NULL) omits null data field on error responses.
25. Why do you use RestClient instead of RestTemplate for Gemini calls?
RestClient is the modern replacement for RestTemplate introduced in Spring 6.1. It provides a fluent, builder-style API that's more readable. RestTemplate is in maintenance mode. RestClient also integrates better with the Spring ecosystem and supports the same underlying infrastructure.
26. What is the purpose of @EnableMethodSecurity?
It enables method-level security annotations like @PreAuthorize("hasRole('ADMIN')") on controller or service methods. This provides defense-in-depth — even if the URL-level configuration is misconfigured, method-level checks provide a second barrier.
27. How does your prompt engineering ensure structured output?
Two mechanisms: (1) The system instruction explicitly says "respond ONLY with valid JSON" and provides the exact schema. (2) The generationConfig sets responseMimeType: "application/json", which tells Gemini to constrain its output to valid JSON. The parsing code still includes defensive handling for edge cases.
28. What is orphanRemoval and why do you use it?
On @OneToMany(orphanRemoval = true): if an InterviewQuestion is removed from the session's question list (but the session itself isn't deleted), Hibernate will automatically DELETE that question from the database. Without it, the question would remain as an orphan row with no parent reference.
29. How would you prevent prompt injection attacks?
Currently, user input (skill name, answer text) is directly interpolated into prompts. A malicious user could inject "ignore previous instructions and..." Mitigations: (1) Input sanitization — strip prompt-like keywords. (2) Use Gemini's system instruction separation (already implemented). (3) Validate AI output structure before trusting it. (4) Rate limit submissions.
30. Why do you use FetchType.LAZY on @ManyToOne?
@ManyToOne(fetch = FetchType.LAZY) on InterviewSession's user field means the User entity is NOT loaded from the database when you load a session — only when you access session.getUser(). This prevents loading the full User object (with all their resumes and sessions) every time you query a single session. It's a critical performance optimization for entities with deep relationship graphs.
